## 上下文
考勤历史页面目前只支持通过员工工号搜索，但用户可能只知道员工姓名而不知道工号。需要添加姓名搜索功能以提高系统可用性。系统使用Go语言后端和LayUI前端框架。

## 目标 / 非目标
- 目标：
  - 在考勤历史页面添加姓名搜索功能
  - 保持现有的工号搜索功能
  - 实现前后端联动的姓名搜索
- 非目标：
  - 不修改现有的考勤历史数据结构
  - 不影响其他页面的搜索功能

## 决策
- 决策：在考勤历史页面添加姓名搜索输入框，并通过修改后端API支持姓名查询
  - 前端添加姓名输入框，与现有工号输入框并列
  - 后端修改查询逻辑，支持通过姓名或工号查询
  - 优先使用工号查询，如果工号为空则使用姓名查询
- 考虑的替代方案：
  - 创建独立的姓名搜索API：需要额外维护，增加复杂度
  - 使用模糊搜索代替精确匹配：可能影响性能，且用户通常知道确切姓名

## 风险 / 权衡
- [风险] 姓名可能重复 → 缓解措施：当姓名匹配多条记录时，显示所有匹配的记录
- [风险] 性能影响 → 缓解措施：为姓名字段添加索引，优化查询语句
- [权衡] 增加代码复杂度 vs 提高用户体验：选择提高用户体验

## 迁移计划
1. 修改前端页面，添加姓名搜索输入框
2. 修改后端处理函数，支持姓名搜索参数
3. 修改服务层查询方法，实现姓名查询逻辑
4. 测试功能，确保与现有功能兼容

## 开放问题
- 是否需要支持姓名模糊搜索？（当前方案支持精确匹配）
- 如果多个员工有相同姓名，是否需要额外标识？（当前方案显示所有匹配记录）
